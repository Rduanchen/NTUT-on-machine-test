# Feature Specification: 考前執行環境自我檢查

**Feature Branch**: `[002-pre-exam-environment-check]`

**Created**: 2026-09-02

**Status**: Draft

**Input**: User description: "建立考前執行環境自我檢查：config 寫入 RAM 後，檢查考試所需語言能正常編譯、執行並正確觸發 TLE/MLE；未通過時禁止進入登入頁，並提供警告 modal 與 system bar 檢測報告。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登入前確認考試執行環境 (Priority: P1)

作為考試系統管理者，我希望桌面程式在收到有效考試設定後，自動驗證本次考試實際需要的每一種程式語言，使考生只能在所有必要環境均可正常判題時進入登入流程。

**Why this priority**: 若編譯器、直譯器或資源限制機制在考試開始後才被發現不可用，將直接阻斷考生作答與本機判題；登入前驗證是本功能的核心價值。

**Independent Test**: 準備只包含一種語言的有效考試設定，確認系統會實際驗證該語言的正常程式、逾時程式與超量記憶體程式，並只在全部符合預期時開放登入。

**Acceptance Scenarios**:

1. **Given** 有效考試設定包含一種或多種支援語言，**When** 設定成為目前使用中的考試設定，**Then** 系統自動檢查每種實際使用語言且不重複檢查同一語言。
2. **Given** 某語言可正常編譯或解譯，且最小程式可產生預期輸出，**When** 該語言完成正常執行檢查，**Then** 報告將正常執行標示為通過。
3. **Given** 某語言執行不會自行結束的測試程式，**When** 到達診斷時間限制，**Then** 系統必須將結果辨識為 TLE 並終止該程式。
4. **Given** 某語言執行持續實際占用記憶體的測試程式，**When** 超過安全的診斷記憶體限制，**Then** 系統必須將結果辨識為 MLE 並終止該程式。
5. **Given** 所有必要語言的全部檢查均通過，**When** 檢查完成，**Then** 系統允許使用者繼續原本的登入流程。

---

### User Story 2 - 阻擋不安全的登入並協助修復 (Priority: P1)

作為考場管理者，我希望任何必要檢查失敗時都能立即看到不可略過的警告及具體失敗原因，修復環境後可以重新檢查，而不是讓考生帶著不可用的環境進入考試。

**Why this priority**: 只有顯示警告但仍可登入，無法避免已知環境故障在考試期間引爆。

**Independent Test**: 在缺少某項必要執行工具的環境載入使用該語言的考試設定，確認登入無法進入、警告持續顯示，補齊環境並重新檢查後才可繼續。

**Acceptance Scenarios**:

1. **Given** 任一必要工具不存在、無法啟動或版本資訊無法取得，**When** 環境檢查完成，**Then** 整體結果為失敗且登入頁不可進入。
2. **Given** 正常執行、TLE 或 MLE 的任一結果不符合預期，**When** 環境檢查完成，**Then** 系統顯示不可略過的警告視窗並保留在登入前流程。
3. **Given** 環境檢查失敗，**When** 使用者直接導向登入頁或由其他頁面觸發登入導航，**Then** 系統仍阻擋登入並顯示目前失敗狀態。
4. **Given** 使用者已修復環境問題，**When** 在警告視窗或檢測報告中選擇重新檢查，**Then** 系統產生新的檢查報告，並在全部通過後開放登入。
5. **Given** 檢查正在執行，**When** 使用者嘗試進入登入頁，**Then** 系統保持阻擋並清楚顯示檢查進度。

---

### User Story 3 - 隨時查看環境檢測報告 (Priority: P2)

作為考生或考場管理者，我希望能從頂端系統列快速知道環境狀態並查看最近一次完整報告，以確認目前可用的語言、工具版本及每項檢查結果。

**Why this priority**: 持續可見的狀態能降低不確定性，並讓現場人員在不重跑測試的情況下取得診斷資訊。

**Independent Test**: 完成一次包含多種語言的檢查後，從頂端系統列開啟報告，確認狀態、時間、平台、語言及各檢查結果均可辨識。

**Acceptance Scenarios**:

1. **Given** 尚未取得考試設定，**When** 使用者查看頂端系統列，**Then** 環境狀態顯示為尚未檢查。
2. **Given** 環境檢查處於執行中、通過或失敗，**When** 使用者查看頂端系統列，**Then** 可用不同且可辨識的狀態呈現目前結果。
3. **Given** 已存在最近一次檢查報告，**When** 使用者按下環境狀態按鈕，**Then** 系統以 modal 顯示報告而不改變目前頁面或考試資料。
4. **Given** 某項檢查失敗，**When** 使用者展開該項結果，**Then** 可看到足以判斷缺少工具、啟動失敗或結果不符的受限長度資訊。

### Edge Cases

- 考試設定沒有任何題目或沒有使用任何程式語言時，檢查完成後以空語言清單標示通過，不應永久阻擋登入。
- 同一語言出現在多個題目、區段或相容的舊格式設定中時，只產生一組語言檢查結果。
- 檢查進行中收到較新的考試設定時，舊設定的結果不得將新設定錯誤標示為通過；最終報告必須對應最新設定。
- 同一時間收到多次重新檢查要求時，不得產生彼此競爭的有效結果或多組不受控的測試程式。
- 工具存在但啟動後無回應、立即崩潰、輸出錯誤或無法產生預期結果時，必須視為失敗並安全結束檢查。
- TLE 或 MLE 測試結束後若測試程式仍存在，該項檢查必須視為失敗。
- 應用程式在檢查期間關閉時，不得留下環境測試程式持續運行。
- 考試已進行後收到設定更新時，系統仍更新環境報告，但不強制離開目前考試頁；新報告的失敗狀態不得被誤呈現為通過。
- 報告中的大量工具輸出或錯誤內容必須受到長度限制，避免檢測畫面或主程式失去回應。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在有效考試設定成為目前設定後，自動開始對應的環境檢查。
- **FR-002**: 系統 MUST 從所有目前有效的題目來源收集實際使用語言，去除重複後形成必要語言集合。
- **FR-003**: 初始版本 MUST 支援 C、C++、Python、JavaScript 與 Java 的環境檢查。
- **FR-004**: 系統 MUST 對每種必要語言確認其編譯或解譯工具可被發現、啟動並提供可辨識的版本資訊；Java 必須分別確認編譯與執行能力。
- **FR-005**: 系統 MUST 對每種必要語言實際執行最小程式，並以預定輸出驗證正常的編譯或解譯及執行能力。
- **FR-006**: 系統 MUST 對每種必要語言執行受控的逾時測試，且只有結果被分類為 TLE 並完成終止時才算通過。
- **FR-007**: 系統 MUST 對每種必要語言執行受控的記憶體超限測試，且只有結果被分類為 MLE 並完成終止時才算通過；測試程式自行發生記憶體錯誤或一般執行錯誤不得算作通過。
- **FR-008**: 診斷使用的時間與記憶體限制 MUST 是安全且有界的，不得依考試設定中的極大限制等量消耗機器資源。
- **FR-009**: 環境檢查 MUST 使用與正式本機判題相同的可用工具鏈與執行語意，使檢查結果能代表實際判題能力。
- **FR-010**: 系統 MUST 維護尚未檢查、檢查中、通過與失敗四種可辨識的整體狀態。
- **FR-011**: 系統 MUST 在狀態為檢查中或失敗時阻擋所有進入登入頁的導航路徑，且不得提供略過失敗的入口。
- **FR-012**: 系統 MUST 在失敗時自動顯示持續存在的警告 modal，內容至少包含失敗語言、失敗檢查及人類可理解的原因。
- **FR-013**: 使用者 MUST 能從警告 modal 與檢測報告重新執行檢查；重新檢查時必須清楚顯示進度並以最新結果取代先前整體狀態。
- **FR-014**: 系統 MUST 在頂端 system bar 提供環境狀態按鈕，以不同的視覺及文字狀態表達尚未檢查、檢查中、通過與失敗。
- **FR-015**: 使用者 MUST 能透過 system bar 按鈕開啟最近一次檢測報告，而不改變目前頁面或考試內容。
- **FR-016**: 每份報告 MUST 包含作業平台、處理器架構、開始與完成時間、必要語言集合，以及每種語言的工具版本、正常執行、TLE、MLE、耗時與錯誤摘要。
- **FR-017**: 系統 MUST 限制報告中的工具輸出及錯誤內容長度，同時保留足以辨識失敗原因的資訊。
- **FR-018**: 新考試設定取代舊設定時，系統 MUST 確保只有對應最新設定的檢查結果能決定目前狀態。
- **FR-019**: 環境檢查 MUST 不新增或修改學生作答檔、分數、公開測試結果、隱藏測試結果或上傳狀態。
- **FR-020**: 系統 MUST 在檢查完成、取消、失敗或應用程式關閉時終止其建立的所有測試程式。
- **FR-021**: 考試已進行後收到設定更新時，系統 MUST 產生對應的新報告，但不得強制將考生導離目前考試頁。
- **FR-022**: 系統 MUST 在 Windows、macOS 與 Linux 的支援版本上提供相同的通過／失敗語意。

### Key Entities

- **環境檢查作業**: 一次針對特定考試設定執行的檢查；包含目前狀態、設定識別、必要語言集合、開始時間、完成時間及整體結果。
- **語言檢查結果**: 某種必要語言的彙總結果；包含所需工具及版本、正常執行結果、TLE 結果、MLE 結果與整體是否通過。
- **單項檢查結果**: 一次具體檢查的結果；包含檢查類型、狀態、耗時、人類可理解的訊息及受限長度的技術摘要。
- **環境檢測報告**: 對使用者呈現的最近一次完整結果；隸屬於一個環境檢查作業，並彙整平台、語言與各單項結果。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 對包含五種支援語言的有效考試設定，100% 的實際使用語言都會各自取得正常執行、TLE 與 MLE 結果，未使用語言不會被列為登入條件。
- **SC-002**: 在任何一項必要檢查失敗或尚未完成的測試情境中，100% 的登入嘗試都被阻擋；全部通過後，登入可在不需重啟應用程式的情況下繼續。
- **SC-003**: 在具備所有必要工具且資源正常的支援平台參考環境中，包含五種語言的完整檢查於 60 秒內完成。
- **SC-004**: 使用者可由頂端系統列在一次操作內開啟最近報告，並能辨識每種語言及每項檢查的通過或失敗狀態。
- **SC-005**: 對缺少工具、工具無法啟動、正常輸出錯誤、TLE 未觸發及 MLE 未觸發的驗收案例，100% 都產生失敗報告及可辨識原因。
- **SC-006**: 每次環境檢查前後，學生作答、成績及判題結果保持完全一致，環境檢查造成的資料變更數為零。
- **SC-007**: TLE、MLE、重新檢查、設定被取代及應用程式關閉的驗收案例結束後 5 秒內，不存在由該次檢查遺留的測試程式。
- **SC-008**: Windows、macOS 與 Linux 的驗收套件均能對相同故障情境產生一致的通過／失敗分類。

## Assumptions

- 考試設定在進入目前設定前已完成既有格式驗證，本功能不負責再次判斷設定格式是否合法。
- 只驗證本次考試實際使用的語言；沒有題目或語言的有效設定視為無環境依賴並可通過。
- 所需編譯器與直譯器可由作業系統環境找到；初始版本不負責下載、安裝、更新或修改系統搜尋路徑。
- 診斷限制以安全地證明保護機制可用為目的，不用來校準特定題目的實際效能或資源額度。
- 最近一次報告只需保留在目前應用程式執行期間，應用程式重新啟動後可重新檢查。
- 設定更新發生在考試進行中時，系統不打斷目前考試頁；登入阻擋只適用於尚未進入登入流程或需要重新登入的使用者。
- 支援平台的實際版本範圍沿用桌面應用程式現行發布政策。

## Scope Boundaries

### In Scope

- 本次考試必要語言的工具可用性、正常編譯或解譯與執行、TLE、MLE 檢查。
- 登入前硬性阻擋、失敗警告、重新檢查及最近報告檢視。
- Windows、macOS、Linux 一致的使用者可見結果。

### Out of Scope

- 自動安裝、下載或打包任何編譯器、直譯器或執行環境。
- 驗證題目本身、測試資料、答案內容、分數計算或特殊規則。
- 以環境檢查結果修改學生作答或正式判題資料。
- 長期保存或上傳環境檢測報告。
