# Feature Specification: 考前預載加密考卷

**Feature Branch**: desktop `feat/003-prefetch-exam-config`；host `feat/prefetch-exam-config`。

**Created**: 2026-10-25

**Status**: Implemented — 自動驗證完成；考場真機驗收待完成

**Input**: 學生輸入學號前斷網後，輸入開考口令會顯示尚未取得考卷；希望階段推進到準備完成時就取得 config。規劃須涵蓋 desktop 與 `/Users/justinchen/Documents/ntut-exam-v2/host`。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 準備完成後可離線登入與開考 (Priority: P1)

監考人員將考試推進到準備完成，已註冊電腦自動取得封存考卷。學生尚未輸入學號就斷網，仍能以合法學號及監考口令進入本次考試。

**Why this priority**: 直接解決現場斷線造成無法開考的問題。

**Independent Test**: 不執行任何學生線上登入，完成考卷預備後拔除網路，以名單內學號及正確口令開考並瀏覽題目。

**Acceptance Scenarios**:

1. **Given** 電腦已註冊且連線正常、尚未登入，**When** 考試進入準備完成，**Then** 自動取得完整封存考卷並顯示離線考卷已備妥，題目仍不可讀。
2. **Given** 離線考卷已備妥且未登入，**When** 斷網後輸入名單內學號及正確口令，**Then** 可開考並讀取題目，恢復連線前不需取得任何伺服器資料。
3. **Given** 已備妥考卷，**When** 輸入錯誤口令，**Then** 拒絕解封，考試不因這次輸入而開始。
4. **Given** 考卷具有非空學生名單，**When** 離線輸入不在名單內的學號，**Then** 拒絕登入。

### User Story 2 - 漏接事件與暫時失敗可自行恢復 (Priority: P1)

電腦在準備完成後啟動、獲准入場或恢復連線，仍會補齊考卷，不需學生先登入。

**Why this priority**: 單靠階段切換事件，會漏掉晚啟動與斷線機器。

**Independent Test**: 在準備完成階段核准一台新啟動機器，取卷時暫時中斷連線，恢復後檢查其可自行備妥。

**Acceptance Scenarios**:

1. **Given** 全域已是準備完成，**When** 電腦完成合法註冊或人工入場核准，**Then** 不等待下一次階段變更即開始備卷。
2. **Given** 下載因網路錯誤失敗，**When** 連線恢復，**Then** 自動重試；仍連線但暫時失敗時，也有定期補抓機會。
3. **Given** 已有本次有效考卷，**When** 後續登入或背景更新失敗，**Then** 不遺失原有考卷，仍可離線解封。
4. **Given** 多個備卷觸發同時發生，**When** 下載尚未完成，**Then** 不重複啟動相同備卷作業。

### User Story 3 - 清楚辨識備卷狀態並避免舊資料混入 (Priority: P2)

學生與現場人員能在登入前確認離線考卷是否備妥；重設考試或更換連線目標後，不會誤用上一場考卷。

**Why this priority**: 避免直到斷線開考時才發現缺少考卷。

**Independent Test**: 模擬取卷中重設，再讓舊下載回覆，確認畫面及本機均未恢復舊考卷。

**Acceptance Scenarios**:

1. **Given** 環境預檢已通過但尚未取得考卷，**When** 顯示登入頁面，**Then** 不顯示離線考卷已備妥。
2. **Given** 備卷失敗，**When** 查看登入或等待頁，**Then** 顯示尚未備妥及可理解的原因，並可手動重試。
3. **Given** 取卷尚未完成，**When** 考試重設、裝置註冊失效或切換伺服器，**Then** 舊作業結果不會重新填入本機。

### Edge Cases

- 從公開狀態查詢得知階段後才完成裝置註冊，需在資格具備時補抓。
- 在下載完成前斷網，僅有口令不足以開考，須清楚顯示缺少考卷。
- 下載中發生考試重設、裝置金鑰變更或被登出，舊結果必須失效。
- 接收到考卷更新但下載失敗時，保留既有考卷並提示更新失敗；離線狀態無法保證得知伺服器最新修訂。
- 環境預檢失敗屬獨立警示，不影響已取得考卷的事實，也不撤銷既有入場核准。
- 開考中才獲准入場，既有正常取卷與開考金鑰流程仍須運作。
- 完全離線匯入考卷的既有流程不需伺服器，仍可正常使用。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 在準備完成階段，為已註冊且連線正常的電腦自動備妥本次封存考卷，不要求先完成學生登入。
- **FR-002**: 系統 MUST 在啟動後得知目前階段、完成合法註冊或人工核准、恢復連線與定期同步時檢查是否需要補抓，不只依賴階段變更。
- **FR-003**: 備卷 MUST 保持題目與測資封存，只有正確監考口令或合法開考金鑰才可解封；取卷本身不得授予學生身分或開始考試。
- **FR-004**: 備妥考卷後 MUST 支援本次程式執行期間在斷網下輸入合法學號及正確口令開考，並沿用既有恢復連線補同步。
- **FR-005**: 學生登入前與等待開考時 MUST 能分辨未取得、取得中、已備妥與失敗狀態；備卷失敗可手動重試，環境預檢結果須獨立呈現。
- **FR-006**: 暫時下載失敗 MUST 可自動恢復；相同資格下並發觸發 MUST 合併為同一作業；失敗不得清除同一場考試已驗證的有效考卷；已知更新在成功取得前 MUST 保留待刷新意圖，下載中收到的新更新也不得因合併請求而遺失。
- **FR-007**: 重設考試、更換伺服器或註冊失效 MUST 清除相應備卷狀態，並拒絕套用失效作業的延遲回覆。
- **FR-008**: host MUST 僅對合法已註冊裝置交付封存考卷，驗證請求新鮮度與完整性；尚未準備考卷、未允許階段或資格失效時不得宣告成功；交付的基本資訊與密文 MUST 來自同一次完整儲存。
- **FR-009**: host MUST 繼續限制自動開考金鑰的釋出條件，預載不改變原本的階段與學生認證要求。
- **FR-010**: desktop 與 host MUST 共同驗證無學生登入的取卷與離線開考流程；不得僅以各端獨立測試通過判定共同部署成功。
- **FR-011**: desktop 本機的考卷及開考金鑰 MUST 僅於本次程式執行期間保留；關閉後的離線重開復原不在本功能範圍。

### Key Entities

- **封存考卷**: 同一次交付的考試基本資訊、允許離線驗證的名單、口令解鎖資訊及題目密文。
- **裝置資格**: 本機對目前伺服器的註冊身分，獨立於學生登入資格。
- **備卷狀態**: 本次執行期間的備卷進度、是否持有有效考卷及最近失敗原因，獨立於環境預檢結果。
- **作業有效範圍**: 用以判定下載回覆是否仍屬目前考試、伺服器與裝置資格的生命週期。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 階段推進、晚核准、漏接事件補查及斷線恢復四種情境，在受控測試各執行 5 次，合計 20 次全部能在不先登入學生的情況下備妥考卷。
- **SC-002**: 已備妥後斷網、登入合法學號及輸入正確口令的情境，連續 10 次均成功進入可讀題目畫面；失敗口令及名單外學號案例全部被拒絕。
- **SC-003**: 以已得知準備完成階段且仍具註冊資格為前提，從暫時錯誤解除起計時，後續取卷於既有 5 秒請求時限內成功回覆的受控情境中，機器於 65 秒內恢復備卷；完成或失敗後 1 秒內更新對應畫面狀態。
- **SC-004**: 重設、切換伺服器與註冊失效三類延遲回覆情境，全部不會恢復舊考卷或錯誤顯示已備妥。
- **SC-005**: 所有考前預載驗收案例中，未提供正確口令或合法開考金鑰時，均無法透過正常學生操作讀取題目與測資。

## Assumptions

- 以使用者指定的準備完成作為必要自動備卷時點；不新增初始化階段立即下載的要求。既有更早手動取卷能力保留。
- 裝置在斷網前已完成合法註冊，並持續開啟應用程式；無法替完全未下載過考卷的斷線機器憑空取得資料。
- 沿用現有監考口令、名單驗證及補同步規則；不新增對空名單的身分政策。
- host 的取卷端點已支援裝置層級驗證；本功能補強交付的資格有效性及配對測試，不需新增公開取卷通道。
- 不新增管理端全班備卷儀表板、跨重啟持久化、遠端離線撤銷或新的考卷版本協定。
- 已實作兩端程式碼並執行自動驗證；實體拔線、考場真機次數與視覺時限仍待驗收。
