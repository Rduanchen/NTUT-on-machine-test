# 考前執行環境自我檢查

怎麼冒出來的：桌面版會在 config 寫入 RAM 後知道本次考試使用的語言；若等學生送出程式才發現編譯器、直譯器或資源限制機制不可用，問題已經發生在不可承受的考試期間。因此需要在登入前以真正的編譯與執行結果建立硬性閘門。

## 問題

工具存在不等於判題環境可用。只執行 `gcc --version`、`python --version` 等命令，無法證明以下整條路徑正常：

- 原始碼可被實際編譯或直譯。
- 編譯後的程式可啟動、接收輸入並產生正確輸出。
- 無限執行的程式會被判為 TLE 並確實終止。
- 超量使用記憶體的程式會被判為 MLE 並確實終止。

本功能的目的不是列出已安裝軟體，而是證明本次考試實際需要的語言能走完桌面判題器的執行路徑。

## 已對齊的需求

### 觸發與閘門

- exam config 經格式驗證並寫入 `ramStore.examConfig` 後，立即開始環境檢查。
- 從 section puzzles 與相容的 legacy puzzles 收集本次使用的語言並去重，只檢查實際需要的語言。
- 環境狀態為 `IDLE | RUNNING | PASSED | FAILED`。
- `RUNNING` 或 `FAILED` 時禁止進入登入頁；只有 `PASSED` 才能繼續。
- 失敗時顯示不可略過的 modal，讓使用者查看結果、重新檢查或關閉應用程式。
- 檢查通過後繼續原本的登入流程。

config 寫入 RAM 是統一觸發點，來源是離線檔案或伺服器不應產生不同的檢查語意。非同步檢查不應直接塞進 RAM store 的同步 setter；應由 config 寫入流程啟動並等待，同時由 router guard 以狀態再次防止繞過。

### 持續可見性

- 最上方 system bar 在伺服器狀態旁提供環境狀態按鈕。
- 按鈕以灰／黃／綠／紅表示尚未檢查、檢查中、通過、失敗。
- 按下後以 modal 顯示最近一次完整檢測結果。
- 失敗報告可由同一處重新檢查；不能提供忽略失敗並進入登入頁的路徑。

### 語言與系統命令

主要運行平台是 Windows，但同一套功能必須支援並測試 Windows、macOS 與 Linux。允許透過 PATH 使用系統命令：

| Config 語言 | 命令需求 |
|---|---|
| C | `gcc` |
| Cpp | `g++` |
| Python | Windows 使用 `python`；macOS/Linux 使用 `python3` |
| JavaScript | `node` |
| Java | 編譯使用 `javac`，執行使用 `java`，兩者皆須驗證 |

環境檢查必須沿用正式判題器相同的命令與參數來源，避免自我檢查通過、正式判題卻使用另一套工具鏈。命令應以 child-process API 的 command/args 形式執行，不透過 shell 拼接。

允許系統命令不等於已否決既有的編譯器打包構想；是否打包工具鏈仍是部署策略。無論工具來自 PATH 或應用程式資源，這份端到端自我檢查都仍然需要。

## 可擴充模組設計

環境檢查應是獨立模組，不把測試細節堆進 config IPC 或 judger IPC。它包含兩個可註冊維度：

- `LanguageProfile`：描述一種語言所需工具及正常、TLE、MLE 測試程式。
- `EnvironmentCheck`：描述一項可獨立增加的檢查及其結果格式。

初始 checks：

1. 工具可發動及版本辨識。
2. 最小程式實際編譯／直譯並驗證指定輸出。
3. 無限迴圈被 runner 判定為 TLE。
4. 分批配置並觸碰記憶體的程式被 runner 判定為 MLE。

未來可在不改動 orchestration 的情況下加入磁碟寫入、process-tree 清除、輸出限制、權限或特定函式庫等檢查。

檢查應使用底層 Judge/runner 的實際路徑，但不能呼叫會保存學生程式、分數或作答結果的正式 `nodeJudgerService.judge()`，否則診斷行為會污染考試狀態。

## 診斷限制與通過條件

### 正常執行

- 必須正常結束並輸出預定 token；只取得版本或 exit code 不足以通過。
- 應保存實際命令、工具版本、耗時及截斷後的錯誤摘要，供 modal 顯示與除錯。

### TLE

- 使用不大量輸出的無限迴圈與短、固定的診斷時間限制。
- 必須由正式 runner 回報 `TLE`，且 process tree 不可殘留。

### MLE

- 測試程式必須分批配置並實際寫入記憶體，避免作業系統 lazy allocation 造成假通過。
- 使用安全、受控且可跨語言調整的診斷限制，不直接按 config 的實際 memory limit 配置；考試若設定極大上限，直接超額配置會讓自我檢查本身危害機器。
- 必須由正式 runner 回報 `MLE`；語言 runtime 自行 Out of Memory 並形成 `RE` 不算通過。
- 各語言循序執行，避免同時進行記憶體壓力測試。

## 報告最小資訊

- 平台、CPU 架構、開始與完成時間。
- 本次 config 所需語言集合。
- 每種語言的工具、版本與各 check 狀態。
- 每項檢查的耗時、訊息及受限長度的技術細節。
- 整體狀態，以及失敗後重新檢查產生的新報告。

## 實作後的驗收方向

- 五種語言各自能證明正常編譯／執行、TLE、MLE；config 未使用的語言不阻擋登入。
- 缺少任一必要命令、命令無法執行、輸出錯誤、TLE/MLE 未被正確分類時，登入頁皆不可進入。
- 直接輸入 `/login` 或從其他頁面導向，也不能繞過環境狀態閘門。
- 通過後能繼續登入，system bar 能再次開啟相同報告。
- Windows、macOS、Linux 對命令名稱、執行檔副檔名及 process-tree 終止均有測試。
- 自我檢查不新增本地作答檔、不改變成績、不寫入公開或隱藏測試結果。
