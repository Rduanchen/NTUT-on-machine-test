# 原則

## 根公理

**離線容錯與最終一致的單一真相**
「後端是資料最終的真相來源 (Single Source of Truth)，但系統必須預設網路是不可靠的。為了確保考生的作答體驗絕不被干擾，前端必須具備離線容錯能力；在斷線期間允許前端作為暫時的真相來源（短暫不同步），但網路一恢復就必須盡速且安全地與後端收斂。」

## 衍生原則

### 1. 本地狀態優先與背景重試 (Local-First & Background Sync)
- **推導自**：離線容錯與最終一致的單一真相
- **意義**：考生的每一次作答，都應該立即寫入並反映在前端的本地狀態（例如 localStorage 或 IndexedDB），不應被後端 API 的延遲或失敗卡住。
- **如何應用**：API 同步必須在背景執行。當發生網路斷線時，將未同步的作答推進離線佇列 (Queue)；當重新連線時，優先消化佇列中的紀錄以盡快恢復同步。
