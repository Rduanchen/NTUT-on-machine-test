# 桌面版測試策略決策 (Desktop Testing Decisions)

## 捨棄 E2E 測試驗證 Local-First 同步衝突

- **情境**：在桌面版的 Local-First 架構下，學生的桌面版環境會優先保存本地的執行結果。當助教在網頁後台透過 Piston 引擎重新執行該學生的程式碼並覆寫後端資料時，學生的本地資料會與後端發生不一致。我們需要測試「當前端與後端重新同步時，前端能識別後端的權威性並正確覆蓋本地舊結果，且不會發生衝突反彈」。
- **被捨棄的選項**：使用 E2E 測試（如 Playwright）同時模擬助教與學生的視窗，點擊 UI 來驗證畫面更新。
- **捨棄原因 (Why)**：
  - 核心痛點純粹是「資料流與合併邏輯的對錯」（Sync/Merge 狀態機），本質上是不涉及畫面複雜渲染的資料運算。
  - E2E 測試執行緩慢、環境設定繁瑣。若用來驗證一個單純的資料覆蓋與邊界條件，開發與維護成本過高，且隔離性差（容易因為其他 UI 變動而 flaky）。
- **最終決策**：將負責處理同步 (Sync) 與合併 (Merge) 的狀態函數抽出，撰寫**單元測試 (Unit Test)**。這樣能以極快的速度與高隔離性，精準餵入 Mock 狀態（舊本地狀態 vs 新 Piston 狀態），100% 確認這段覆蓋邏輯的正確性。
